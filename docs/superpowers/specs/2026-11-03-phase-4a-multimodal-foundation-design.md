# Phase 4A 设计：内容单元与视觉资产基础

- 日期：2026-11-03
- 状态：设计待评审，尚未实现
- 分支：`feat/m4-multimodal-foundation`
- 上层方案：`docs/AGENTIC-RAG-ENTERPRISE-ROADMAP.md` §5.5；4A～4E 拆分已确认

## 1. 目标与可见结果

让每个知识内容单元可以关联到固定文件版本的原件和视觉资产，作为 OCR、图表解析和视觉回答的共同基础。

以一个两页、具有文本层的 PDF 为例：上传后仍能检索正文；文档查看窗口能列出两张页面图；查看某个子块时能识别其对应页面资产。当天再上传同名但内容不同的 PDF，两份原件和页面图互不覆盖。重启后这些关联仍可读取。

本阶段实现全局知识库链路。纯扫描件问答属于 4B，图表理解属于 4C/4D，引用点击后的区域高亮属于 4E。不能仅凭生成了图片就将这些能力标记为完成。

## 2. 现有代码基础与已知限制

| 位置 | 当前能力 | 4A 的处理 |
|---|---|---|
| `RagFileAppServiceImpl` | 原件保存、解析、ES 索引、失败标记、删除编排 | 在此接入内容元数据与页面资产生命周期 |
| `ParsedChunk` / `KnowledgeChunk` | 正文＋位置 metadata，支持父子块 | 继续复用，不新增平行的内容单元表 |
| `PdfDocumentParser` | 逐页抽文本，真实页码；空页跳过 | 保持文本行为；页面图按实际页码关联，不按非空 chunk 序号猜测 |
| `ExcelDocumentParser` | 表头、合并单元格、Sheet/行与父块 | 保持原行为，新增元数据不能破坏父子块展开 |
| `StorageService` | 日期＋文件名，写入时允许替换 | 新写入使用唯一键；旧相对路径不迁移 |
| `KnowledgeIndexRepository` / ES 适配器 | 检索字段＋metadata，二进制不入索引 | 增量保存类型、资产 ID 和位置 |
| `AgentCitation` / `AgentCitationService` | 文件、版本、页码、摘录包含性核对 | 4A 不改回答和核验语义；4E 扩展视觉引用 |
| `app.js` 文档窗口 | 原件、分块查看 | 增加页面资产列表、图片预览与对应关系 |

已有原件可能被同名上传覆盖，无法从当前内容恢复历史字节；4A 只保证新写入不再覆盖，不为旧数据伪造恢复结果。当前版本号来自 `rag_file` 记录，删除重传时不保证逻辑版本号永久递增；4A 使用 `fileId + documentVersion` 标识归属，绝不只按文件名或版本号找原件。逻辑文档版本和历史保留策略由 Phase 5 完善。

## 3. 设计取舍

采用“现有 chunk 渐进扩展＋一张资产表＋现有本地存储”。不另建同时保存正文的 `content_unit` 表，不增加通用媒体微服务。

其他路径的取舍：把资产全部放 ES 会混淆检索与二进制生命周期；立即引入对象存储、队列和完整 DocumentVersion 体系会把 Phase 5 的范围带入本阶段。当前选择优先交付可运行、可验证的基础，并让存储键不依赖本机绝对路径。

### 3.1 内容单元

Content Unit 是可检索、可定位的内容概念，继续通过 `ParsedChunk` → `KnowledgeChunk` 表达，正文仍是 `content`。新增字段写入统一约定的 metadata，并由一个映射位置统一校验和转换，避免各解析器重复拼装。

| 字段 | 含义与规则 |
|---|---|
| `contentUnitId` | 本轮摄取内的内容单元 ID；4A 的 CHILD 块直接复用现有 `chunkId`，不产生第二套 ID |
| `contentType` | `TEXT / TITLE / TABLE / IMAGE`；4A 现有解析输出按真实类型标注，不能仅凭文件是 PDF 就标为 IMAGE |
| `assetId` | 关联视觉资产；纯文本文件为空，PDF 子块可关联所在页面图 |
| `location` | 来源位置，见下节；缺失字段为空 |
| `parserVersion` | 服务端维护的解析实现版本；4A 新摄取必须填写 |
| `modelVersion` / `promptVersion` | 仅实际使用模型生成内容时填写，4A 留空 |

`contentType` 是内容类型，`chunkType=CHILD/PARENT` 是检索组织方式，两者独立。父块由多个子单元聚合，不继承第一个子块的 `contentUnitId`、`assetId` 或精确位置；跨多个位置时只保留确实共享的定位信息。父块恢复不能把整段父块误记为一张图片的内容。

4A 不修改既有 `chunkId`、父子块分组规则或 embedding 输入。未来若一个内容单元进一步拆成多个检索块，再显式扩展单元与块的关系。

### 3.2 来源位置

使用一个可复用的 `ContentLocation` DTO，必要的 `BoundingBox` 作为其嵌套值类型；不为每种格式建立独立的上下文类。

| 字段 | 规则 |
|---|---|
| `page` | PDF 页码，从 1 开始；不拿文本 chunk 序号代替 |
| `sheetName` / `cellRange` | Excel 的工作表与如 `B3:F12` 的区域；只有行号时保留已有 `rowIndex`，不猜测列范围 |
| `slide` | PPTX 幻灯片序号，从 1 开始 |
| `anchorId` | DOCX 段落/表格/图片锚点，或 Office 形状标识；不冒充页码 |
| `boundingBox` | `x/y/width/height`，以显示方向的原始页面或幻灯片左上角为原点，归一化到 `[0,1]` |

坐标必须满足有限数值、正宽高和边界约束；处理页旋转时同步转换坐标。独立图片以自身为坐标平面。裁剪图的位置始终指向原始来源平面，通过 `sourceAssetId` 关联来源资产，避免多次裁剪后坐标含义变化。

4A 的 PDF 文本块只有真实页码，精确文本 bbox 保持为空。页面资产本身可以使用覆盖整页的 bbox，但这不代表已经识别出文字、表格或图表的区域。

### 3.3 视觉资产表

新增 `DocumentAssetEntity`，表名 `rag_document_asset`，只保存元数据，不保存图片字节。原件继续由 `rag_file.storage_path/sha256` 管理，避免双份登记。

| 字段 | 含义 |
|---|---|
| `id` | 服务端生成的 UUID，作为外部 `assetId` |
| `fileId` / `documentVersion` | 所属 `rag_file` 和该次文档版本，均不能为空 |
| `assetType` | `PAGE / REGION / EMBEDDED_IMAGE`；4A 只实际生成 PAGE |
| `assetIndex` | 本文件内的稳定展示序号，用于分页排序；不是页码 |
| `storageKey` | 本地存储根目录下的相对对象键，不是绝对路径或外部 URL |
| `mimeType` | 实际编码 MIME；4A 页面图为 `image/png` |
| `sha256` / `byteSize` | 图片内容摘要及字节数，用于一致性核对和限额 |
| `width` / `height` | 实际图像像素尺寸，均为正数 |
| `sourceAssetId` | 裁剪来源资产；PAGE 为空，后续 REGION 必须属于同一文件版本 |
| `locationJson` | 持久化 `ContentLocation`；长文本使用项目约定的 CLOB，不存任意反序列化类型 |
| `parserVersion` | 生成该资产的服务端实现版本 |
| `createdAt` | 生成时间 |

领域 Repository 只定义按归属读取、列举、保存和删除；JPA 实现放在 infrastructure。DTO 使用 record，实体使用 class＋Lombok；新 Java 文件含 `@author raosaijie`，实体每个字段都写含义注释。

查询必须校验 `fileId + documentVersion + assetId` 的关系。UUID 不代表权限，不能因为知道一个 ID 就绕过所属文件检查。当前仍继承全局知识库的共享访问语义，不能宣称已具备 Phase 7 的多租户 ACL。

## 4. 本地存储与页面渲染

### 4.1 原件存储

- 新原件键采用 `originals/日期/UUID/清洗后的文件名`，使用不覆盖已有文件的写入方式；内容指纹与原有上传去重语义保持不变。
- 页面资产键采用 `assets/{fileId}/v{documentVersion}/{assetId}.png`；任何键都由服务端生成，接口不接受客户端存储路径。
- 继续从 `fileagent.storage-dir` 读取根目录；数据库和接口不暴露本机绝对路径。
- 读取/删除继续校验路径在根目录内，并拒绝通过符号链接越出根目录。只操作解析出的单个对象，不按用户输入递归删除目录。
- 旧 `storage_path` 原样可读，不移动或重命名旧文件；旧记录没有资产时返回空列表，不自动调用渲染器回填。删除旧记录时若路径仍被其他知识文件或会话附件引用，只删除当前记录，不删除共享字节。
- `StorageService` 为会话附件和知识库共用；唯一键写入同时覆盖两种调用者的存储行为，但不扩展会话附件索引流程。会话附件上传去重命中后，清理本次刚产生且没有被记录引用的临时副本。

### 4.2 PDF 页面渲染

复用项目已有 PDFBox，仅生成页面预览，不在 4A 引入 OCR、VLM 或新的外部解析服务。按实际页码顺序处理，一次保留一页的中间图像；页面图生成成功后写入资产表。

配置放在主应用 YAML 的 `fileagent.multimodal` 下，以下为待实现配置，不表示当前程序已支持：

```yaml
fileagent:
  multimodal:
    enabled: false
    render-dpi: 120
    max-pages: 100
    max-page-pixels: 4000000
    max-total-asset-bytes: 67108864
```

- 关闭时保留当前解析和索引功能，不生成页面资产；新原件唯一键保护始终生效。
- 开启时先检查 PDF 页数、页面尺寸及预计渲染像素，再逐页生成；超过限额明确失败，不悄悄跳页并声称完整成功。
- 页数、单页像素、累计字节均有硬上限；达到限制即停止，释放文档和图像资源，执行失败清理。
- 图片编码写入受累计计数限制的流，超限时停止并删除本次未完成对象，不先在内存聚合整份文档的图片再做大小检查。
- 超大页面不先完整解码再判断限额；损坏或加密且无法读取的文件返回受控解析错误。
- 4A 不提供对外“任意裁剪图片”接口；REGION 的生成与实际版面识别在 4B/4C 接入。

## 5. 上传、读取和删除流程

### 5.1 上传

```text
原有上传去重检查
  → 保存 rag_file(PARSING) 与唯一键原件
  → 原有解析器生成 ParsedChunk
  → 开启多模态时检查并生成 PDF 页面资产
  → 为 CHILD 填充类型、位置、解析版本及对应 assetId
  → 保持既有父子块规则写入 ES
  → 更新 rag_file(SUCCESS)
```

资产记录和 ES 不共享数据库事务，不能声称一次事务覆盖全部步骤。以 `rag_file.status` 控制新资产对外可见性；只有所属文件 SUCCESS 且版本匹配才允许列举/读取。本阶段使用现有同步上传，无需新增队列、摄取状态机或后台修复服务。

上传发生可捕获失败时：先清理该文件 ES 片段，再删除本轮生成的资产对象和资产行，最后标记 FAILED；保留原件排查。清理失败记录 `fileId/assetId/阶段` 并保留可重试的元数据，不能以成功状态吞掉失败。

进程强制退出可能留下 PARSING 记录和未公开资产；当前没有持久化摄取任务恢复，4A 不宣称自动续传。验证时确认这些资产不会被公开；修复/重放及崩溃孤儿定期回收归 Phase 5，运维清理只能按该文件实际记录定位对象。

### 5.2 读取

1. 读取所属 `rag_file`，检查文件存在、SUCCESS、版本匹配。
2. 读取资产行并核对归属，不按文件名查找其他记录补位。
3. 解析受约束的存储键，检查对象存在与大小；提供流式二进制响应，不整体读入大 byte 数组。
4. 对象缺失时返回明确错误；不现场重画、换版本或替换成其他同名图片。

### 5.3 删除

保留“先删除 ES 再删文件记录”的约束：

```text
校验文件可删除
  → 删除该 fileId 的 ES 索引
  → 按资产记录逐一删除二进制，成功后删除对应资产行
  → 删除原件
  → 删除 rag_file
```

对象不存在视为已删除；IO 失败不能仅打印日志后删除元数据，需中止并保留重试依据。重复删除过程中已完成的单步不会误删其他文件。4A 不承诺彻底删除后仍可展示历史原图，历史引用保留已有摘录，资产入口明确显示不可用；版本保留策略由 Phase 5 决定。

## 6. API 与前端（拟实现）

| 接口 | 行为 |
|---|---|
| `GET /api/rag-files/{fileId}/assets?documentVersion=1&afterAssetIndex=-1&limit=20` | 返回 `ApiResult` 包装的资产摘要页，含 `items/nextAssetIndex`；limit 最大 50，游标排他，不因前 20 项截断全部结果 |
| `GET /api/rag-files/{fileId}/assets/{assetId}/content?documentVersion=1` | 校验归属后返回固定 MIME 的流式图片，二进制不套 `ApiResult`；声明 `nosniff`，不支持任意外部 URL |
| 现有 `GET /api/rag-files` | 在文件摘要中追加可空 `documentVersion`，供前端使用服务端真实版本；兼容旧 DTO 构造和旧客户端 |
| 现有 `GET /api/rag-files/{fileId}/chunks` | 保持原结构，在 metadata 中增加内容单元字段；不返回向量、存储键或绝对路径 |

`documentVersion` 为新资产接口必填参数，避免历史访问自动落到新版本。前端使用文件摘要中的真实版本，不硬编码 1；旧记录版本缺失时不调用资产接口，显示无可用页面资产。资产摘要含 `assetId/documentVersion/assetType/assetIndex/location/mimeType/width/height/byteSize`，不包含 `storageKey`。同一格式的位置通过 `ContentLocation` 返回。

资产不存在、归属错误和版本不匹配统一按 404 处理，避免跨文件返回图片；参数非法按业务 400。旧文件存在但没有资产时列表返回空页。实现时同步更新 `docs/API.md`，此设计稿中的接口尚未生效。

前端复用当前文档查看窗口，增加“页面图片”入口；按需加载缩略图并分页，点击查看对应页面大图。分块区域显示内容类型、真实页码及关联资产入口；没有资产时显示“暂无页面图片”，不提示 OCR 已完成。4A 不渲染不存在的文本 bbox，也不新增图表推理界面。

## 7. 索引与兼容规则

- 保留既有索引、检索排序、chunk ID 和向量维度，不重建全部向量。
- 顶层仅补 `contentUnitId/contentType/assetId/parserVersion` 的 keyword mapping；完整 `location` 与可选生成版本保存在既有 metadata 中。旧 `page/sheetName/rowIndex` 的写入继续由同一映射逻辑保持一致。
- 对新摄取校验位置和资产归属后再写 ES；未知 metadata 不直接作为可信文件路径或资产权限。
- 旧索引缺少 `contentType` 时只在读取视图上兼容为 TEXT；新加的 `contentUnitId/assetId/parserVersion/location` 缺失保持空，不写回伪造资产或版本。
- 已有页码/Sheet 元数据仍可读取；缺失坐标不生成虚假区域。没有 assetId 不影响普通文本回答。
- Agent 的精读、最终上下文登记、回答与引用 JSON 保持现有契约；4D/4E 再补实际使用的视觉证据及引用字段，不提前让工具可见。

## 8. 实施批次与验收

| 任务 | 范围 | 验证证据 |
|---|---|---|
| 1 | 内容类型、位置契约和资产实体/Repository | 字段含义完整；位置校验、归属读取与持久化测试 |
| 2 | 原件唯一键和资产对象读写 | 同名不同内容、并发写入、旧路径读取、路径/符号链接边界测试；会话附件存储回归 |
| 3 | PDF 页面图生成与限额 | 两页 PDF、旋转页、空白页、超页数/像素/字节、损坏文件的真实渲染测试 |
| 4 | 上传/ES/删除接入 | 页面与 chunk 正确关联；父块不继承错误资产；索引和清理故障注入测试 |
| 5 | 资产 API 与兼容 | 分页超过 20 项可取全；跨文件/版本拒绝；旧索引/无资产文件可读 |
| 6 | 文档窗口展示与端到端验收 | 实际浏览器上传、查看两页图、读取分块、刷新、删除后的行为及移动端检查 |

所有任务完成才算 4A 完成。仅新增实体、空接口或 Mock 页面不算交付；页面图测试使用真实 PDFBox 渲染，不以 Mock 渲染替代。

建议验收样本：两页文本 PDF（含旋转页）；带空白页的 PDF；同名不同内容文件各一份；TXT/MD/DOCX/XLSX 旧功能样本；超过 20 页的 PDF；损坏及超限 PDF。4B 再加入扫描正文及 OCR 质量样本。

文档变更使用 `git diff --check` 和引用路径检查；实现阶段运行 document 域对应测试、ES 集成测试与主应用前端契约检查，并执行真实浏览器验收。任何依赖环境未运行的验证明确记录，不能把单元测试通过等同于部署验收。

## 9. 本次评审需要确认的结论

1. 复用现有知识块，只新增一张视觉资产表；不重复保存全文内容。
2. 4A 真正交付 PDF 页面图片、唯一键原件、资产 API 与前端可见入口，OCR 在 4B 接入。
3. 新原件不覆盖旧对象；旧数据不自动迁移；历史引用不跳到同名新文件，彻底删除后允许显示资产不可用。
4. 页面资产先本地存储并受资源上限约束，对象存储和持久化摄取恢复留到 Phase 5。

上述设计通过评审后，再编写可执行的实现计划并开始业务代码开发。
