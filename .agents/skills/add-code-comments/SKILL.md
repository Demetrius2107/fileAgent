# add-code-comments — 标准化代码注释

给本仓库的 Java 代码补充/生成标准化注释。**仓库规范事实源：`docs/COMMENT-STYLE.md`（本文档与之一致，若有冲突以 COMMENT-STYLE.md 为准）。**

## 何时使用

- 用户要求"加注释 / 补注释 / 写注释 / 标准化注释 / 按规范注释"
- 用户要求新代码必须带类级 + 方法级注释
- 审查代码时发现公开类/方法缺 Javadoc，需要补齐

## 核心原则（来自 COMMENT-STYLE.md）

1. **注释是约束，不是解释**：写"为什么这样设计 / 有什么限制 / 有什么前置条件"，不写"这行在干嘛"。
2. 注释密度与相邻文件一致；命名能表达的就不加注释。
3. 中文注释统一；行内注释 `//` 前空一格。
4. 待办必须带里程碑责任人：`// TODO(B): ...`，禁止裸 `// TODO`。

## 执行步骤

对每个需要补注释的 Java 文件：

1. **读文件**：先 Read 目标文件，理解类职责、方法行为、字段含义，不要凭空写。
2. **类 / 接口 / 枚举**：在声明上方加**标准化头部注释块**（含元信息标签，见下方模板与 `docs/COMMENT-STYLE.md` §2 标签表）。枚举在头部块外再为每个值说明含义。
3. **更新头部块**：改动已有类时，刷新 `更新时间`；里程碑变更时更新 `版本/状态`；创建时间与作者保持固定。
3. **公开方法**：行为不显然（对外契约 / 有副作用 / 有前置条件）的方法加 Javadoc：职责一句话 + `@param` / `@return` / `@throws`（只在信息量足够时写）。简单 getter/setter、显而易见的委托方法**不写**。
4. **私有方法**：仅在隐藏了关键约束时写一行说明，如 `/** 从相对路径解析绝对路径，防路径穿越 */`。
5. **行内注释**：只补"为什么"，不补"做什么"；删除重复代码的流水账注释。
6. **编译验证**：改完跑 `mvn -o -ntp compile -pl <模块> -am`（需 JDK 21，`JAVA_HOME=D:/jdk21`），确认无语法错误。
7. **不直接 commit**：本仓库约定代码改动不直接提交，留工作区/暂存区供用户本地 review（除非用户明确要求提交）。

## 模板

### 类 / 接口（标准化头部注释块）

用**固定标签集**的头部注释块，模板见 `docs/COMMENT-STYLE.md` §2。完整示例：

```java
/**
 * ====================================================================
 * 类名     ：StorageService
 * 描述     ：本地文件存储服务（落盘 + sha256 + 防目录穿越）
 * 所属模块  ：fileagent-document
 * 作者     ：Demetrius
 * 创建时间  ：2026-08-22
 * 更新时间  ：2026-08-22
 * 版本     ：0.1.0
 * 状态     ：M1 完成
 * 依赖     ：StorageService → StorageProperties / MessageDigest
 * 备注     ：返回相对路径，便于后续迁移 OSS（只改本类，Entity 不动）
 * ====================================================================
 */
```

标签规则（必填 ✅ / 选填 ⭕）：`类名`✅ `描述`✅ `所属模块`✅ `作者`✅ `创建时间`✅ `更新时间`✅ `版本`✅ `状态`✅ `依赖`⭕ `备注`⭕。
**更新规则**：创建时间固定；**每次改动代码刷新更新时间**；里程碑变更改版本与状态；注释与逻辑必须同步。

### 方法（公开 / 不显然）

```java
/**
 * 做什么 + 为什么（副作用 / 前置条件）。
 *
 * @param xxx 参数含义
 * @return 返回含义
 * @throws BizException 何时抛出
 */
```

### 记录（record）

```java
/** 一句话说明这个 DTO/值对象的用途 */
public record Xxx(...) { }
```

## 检查清单（完成后自查）

- [ ] 新增/公开类、接口、枚举有职责 Javadoc？
- [ ] 不显然的公开方法有 Javadoc？简单委托方法**没有**硬加？
- [ ] `@param/@return/@throws` 只在信息量足够时写，没凑数？
- [ ] 行内注释只解释"为什么"，没有重复代码的流水账？
- [ ] 没有裸 `TODO`（必须是 `TODO(责任人):` 或 `TODO(M里程碑):`）？
- [ ] 编译通过，改动未直接 commit（留工作区待 review）？
