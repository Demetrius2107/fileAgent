# 注释规范 (COMMENT-STYLE.md)

> 目标：注释只补"代码表达不了的信息"，不重复代码、不写流水账。让 AI 代理与协作者产出风格一致的注释。

## 1. 总原则

- **注释是约束，不是解释**：写"为什么这样设计/有什么限制"，不写"这行在干嘛"。
- 好代码优先靠**命名**表达意图；命名清楚了就不需要注释。
- 注释密度与相邻文件一致。

## 2. 类 / 接口 / 枚举注释

**类/接口/枚举使用 Javadoc 标签式注释**（对齐阿里/字节规范：必须 Javadoc + 必须创建者与创建日期），放在声明上方：

```java
/**
 * 本地文件存储服务：负责文件落盘、sha256 指纹计算与路径安全校验。
 * 返回相对路径，便于后续迁移 OSS（只改本类，Entity 不动）。
 *
 * @author Demetrius
 * @since 0.1.0
 * @date 2026-08-22
 */
```

### 结构要求

1. **描述段**（正文）：一句话说清"做什么 + 关键约束"（它是"什么、负责什么"，不罗列字段）。这是阿里/字节的核心强制项。
2. **`@author`**：创建人，写个人名（两人仓库各自写自己的）。
3. **`@since`**：创建时对应的项目版本（见根 pom `<version>`）。
4. **`@date`**：创建日期 `YYYY-MM-DD`，创建即固定。

### 明确不做（重要）

- **不写"更新时间/更新历史"**：更新历史一律交给 git（`git log` 可查），注释里写更新时间必然过期变脏。
- **不写横幅块**（`类名/描述/所属模块/项目名称/Copyright` 那类）：冗余信息，模块从包名可读，版权归仓库级（LICENSE）。
- **`版本` 不逐文件维护**：仅在 `@since` 记录创建时版本，里程碑级版本变更不逐文件回写。

### 其它

- 枚举在 Javadoc 之外，为每个枚举值补一行含义说明（强制）。
- `@Deprecated` 必写原因与替代。

## 3. 方法注释

仅当方法行为**不显然**（对外契约 / 有副作用 / 有前置条件）时才写 Javadoc：

```java
/**
 * 上传并解析文档，返回解析结果（含分块数）。
 * @throws BizException 当文件类型不支持时
 */
public UploadFileResp handleUpload(MultipartFile file, Long sessionId) { ... }
```

- 简单 getter/setter、显而易见的方法**不写**。
- `@param / @return / @throws` 只在信息量足够时写，不凑数。

## 4. 行内注释（inline）

- 用来说明"为什么"，不用来说明"做什么"：
  ```java
  // 先持久化实体再建索引，避免索引指向已删行
  docRepo.save(doc);
  vectorStore.add(chunks);
  ```
- 中文注释统一；同一行内注释空一格再写 `//`。
- 禁止 `// TODO xxx` 不写责任人；待办要带里程碑，如 `// TODO(M2): 异步解析`。

## 5. 禁止项（Red Lines）

| 禁止 | 反面示例 |
|---|---|
| 重复代码的注释 | `int i = 0; // 把 i 设为 0` |
| 大段复制粘贴的英文模板注释 | 每行都写 `// 获取用户列表` |
| 遮挡性注释 | 整段删掉代码改成注释 |
| 无信息量的空 Javadoc | `/** 方法 */` |
| 注释与实际不符 | 逻辑改了注释没改（**必须同步**） |

## 6. LLM 提示模板注释

- `resources/prompts/*.st` 里用注释标注变量占位含义，如 `{question_context}` 是检索片段。
- 模板注释要写清"约束 LLM 输出什么格式"，这是提示词的一部分。

## 7. 检查清单

- [ ] 新增类/接口有职责 Javadoc？
- [ ] 复杂方法有"为什么"注释？
- [ ] 没有重复代码的流水账注释？
- [ ] 没有 `System.out`、没有裸 `TODO`？

---

## 8. 自动化执行

本规范已封装为可触发的注释技能 **`add-code-comments`**（位于 `.agents/skills/add-code-comments/SKILL.md`，随仓库共享）。

- 触发词："加注释 / 补注释 / 写注释 / 标准化注释 / 按规范注释" 等。
- 技能会自动按本规范执行：类级/方法级模板 → 行内"为什么"注释 → 编译验证 → **不直接 commit**（留工作区供 review）。
- 当用户要求"以后的代码都要有注释 / 自动生成注释"时，直接调用该技能。
