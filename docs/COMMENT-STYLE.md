# 注释规范 (COMMENT-STYLE.md)

> 目标：注释只补"代码表达不了的信息"，不重复代码、不写流水账。让 AI 代理与协作者产出风格一致的注释。

## 1. 总原则

- **注释是约束，不是解释**：写"为什么这样设计/有什么限制"，不写"这行在干嘛"。
- 好代码优先靠**命名**表达意图；命名清楚了就不需要注释。
- 注释密度与相邻文件一致。

## 2. 类 / 接口 / 枚举注释

一律用中文 Javadoc 说明**职责**（一句话 + 关键点），放在声明上方：

```java
/**
 * 会话消息（保存单轮对话，assistant 消息携带 actionJson）
 */
public class MessageEntity { ... }
```

- 说明"它是什么、负责什么"，不罗列字段。
- 枚举可说明每个值含义；`@Deprecated` 必写原因与替代。

## 3. 方法注释

仅当方法行为**不显然**（对外契约 / 有副作用 / 有前置条件）时才写 Javadoc：

```java
/**
 * 上传并解析文档，返回解析结果（含分块数）。
 * @throws BizException 当文件类型不支持时
 */
public UploadFileResp handleUpload(MultipartFile file, Long sessionId) { ... }
```

- 简单 getter/setter、显而易见的方法**不写**。
- `@param / @return / @throws` 只在信息量足够时写，不凑数。

## 4. 行内注释（inline）

- 用来说明"为什么"，不用来说明"做什么"：
  ```java
  // 先持久化实体再建索引，避免索引指向已删行
  docRepo.save(doc);
  vectorStore.add(chunks);
  ```
- 中文注释统一；同一行内注释空一格再写 `//`。
- 禁止 `// TODO xxx` 不写责任人；待办要带里程碑，如 `// TODO(M2): 异步解析`。

## 5. 禁止项（Red Lines）

| 禁止 | 反面示例 |
|---|---|
| 重复代码的注释 | `int i = 0; // 把 i 设为 0` |
| 大段复制粘贴的英文模板注释 | 每行都写 `// 获取用户列表` |
| 遮挡性注释 | 整段删掉代码改成注释 |
| 无信息量的空 Javadoc | `/** 方法 */` |
| 注释与实际不符 | 逻辑改了注释没改（**必须同步**） |

## 6. LLM 提示模板注释

- `resources/prompts/*.st` 里用注释标注变量占位含义，如 `{question_context}` 是检索片段。
- 模板注释要写清"约束 LLM 输出什么格式"，这是提示词的一部分。

## 7. 检查清单

- [ ] 新增类/接口有职责 Javadoc？
- [ ] 复杂方法有"为什么"注释？
- [ ] 没有重复代码的流水账注释？
- [ ] 没有 `System.out`、没有裸 `TODO`？
